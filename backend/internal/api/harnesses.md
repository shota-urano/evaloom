# Harness APIの実装

登録テーブルの正本は`docs/specs/02-data-model.md`の3.2節。
Harnessは名前、リポジトリのURLとローカルの複製のパス、直接振り分けの既定のProfile、
承認を省く設定を持つ。Adapter、モデル、ツールとその許可はProfile定義に持つ。

既存のリポジトリ検査は、実ディレクトリ、Gitのルート、originのURLを確かめる。
実パスを保存し、別のHarnessが同じリポジトリを登録していれば409を返す。
Runnerの作業ディレクトリはRunnerの設定に持つため、このAPIはDBから取得しない。

既定のProfileは同じHarnessに属する必要がある。承認を省く操作は、その版の宣言で
省略を認められたものに限る。既定の版がNULLなら承認を省く設定は空配列に限る。
変更前後の値と監査記録は同じトランザクションで保存する。
