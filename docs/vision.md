# Evaloom とは

この文書は、Evaloom が何をするもので、何をしないものかを決める正本である。requirements.md と docs/specs/ の仕様は、この文書に従う。食い違ったときは、この文書に合わせて requirements と仕様を直す。この文書を変えてよいのは本人だけである。

2026-11-09〜10 の本人との相談をもとに書いた。末尾に本人の言葉を原文のまま残す。

## 1. 一言で

Evaloom は、Linear などから仕事を受け取り、どの Project またはハーネスに頼むかを決めて振り分け、結果を返すオーケストラである。仕事そのもの（作業し、確かめ、出す）はハーネスが行う。

開発の仕事だけを扱うものではない。開発、X の運用、調査など、種類の違う仕事を同じ仕組みで扱う。小さなアプリやハーネスを重ねていくための土台にする。

## 2. Evaloom がやること

1 件の仕事は、次の流れで進む。Evaloom が受け持つのは 1・2・3・7・8 である。

| 段 | 中身 | 担当 |
|---|---|---|
| 1 入る | Linear から仕事を受け取る。手動でも作れる。ほかの入口（定期実行など）は後で足す | Evaloom |
| 2 振り分ける | どの Project またはハーネスに頼むかを、Issue のラベルで決める。ラベルが無い、または決まらないときは、AI が Issue を読んで振り分け先を提案し、本人が承認してから実行する | Evaloom |
| 3 順番待ち | 同時に動かす数を制御し、状態を管理する | Evaloom |
| 4 作業する | 仕事の中身をこなす | ハーネス |
| 5 確かめる | 結果が基準を満たしているかを確かめる | ハーネス |
| 6 出す | 結果を外に出す（PR、下書き、コメントなど） | ハーネス |
| 7 承認する | 本人の承認が要る操作を、操作の直前に本人に承認してもらう | Evaloom |
| 8 返す | Linear へのコメントと状態の変更、通知、管理画面、記録 | Evaloom |

加えて、Evaloom は次を受け持つ。

- **ハーネスの登録と版の固定**: どのハーネスのどの版で仕事をしたかを記録する。
- **安全な場所の用意**: 5 と 6 の中身はハーネスが決めるが、作業中の AI が書き換えたり、鍵を使ったりできない場所で動かす。その場所（隔離、鍵の保管、決まった版から読み出すこと）を用意するのは Evaloom である。7 で何を承認の対象にするかはハーネスが宣言し、承認の画面と記録は Evaloom が持つ。
- **記録と受け渡し**: ハーネスの成果物を記録として持ち、同じハーネスの次の仕事に参考として渡す。
- **振り分けの提案**（2026-11-10 本人決定）: 振り分けはラベルで決めるのが基本である。ラベルで決まらない Issue だけ、AI が中身を読んで「実行場所はこれでよいか」を提案し、本人の承認を待つ。AI は提案するだけで、承認なしに実行を始めない。承認は管理画面でも Linear でも受け付ける。Linear では、AI が提案をコメントし、本人が提案されたラベルを Issue に付けたら承認とみなす。Issue の本文は外から来た文であり、AI がそれに引きずられて誤った振り分けをしても、本人の承認で止められるようにするためである。

## 3. Evaloom がやらないこと

- 仕事の中身（4・5・6）を決めること。例えば worktree、テスト、PR は開発ハーネスのやり方であり、Evaloom の仕組みとしては持たない。
- 特定の種類の仕事を前提にすること。Project（Git リポジトリ）は振り分け先の1つであり、振り分け先そのものではない。リポジトリを持たない仕事は、ハーネスに直接振り分ける。
- 仕事の種類に固有の情報を持つこと（2026-11-10 本人決定）。例えば開発のテストコマンドや setup は、開発ハーネスが持つ。Evaloom は必要なときにハーネスを見にいく。Evaloom の Project が持つのは、名前、振り分けのラベル、頼むハーネス、そのハーネスに渡す値（中身は Evaloom が解釈しない）だけにする。モデルが起こす失敗への対策も、各ハーネスの中で完結させる。
- 本人の代わりに外へ公開すること。公開やマージのような戻せない操作は、本人の承認を通す。

## 4. 迷ったときの基準

- **その処理は、仕事の種類によって中身が変わるか。** 変わるならハーネスの管轄、変わらないなら Evaloom の管轄である。
- **作業中の AI が、合否の基準や鍵に触れられるか。** 触れられるなら、置き場所が間違っている（requirements 原則13・14・15）。
- **本人が「思っていたのと違う」と言える形で見せたか。** 仕様を確定する前に、仕事が入ってから返るまでの流れ図を本人に見せる。

## 5. ハーネスとの約束と鍵

- Evaloom とハーネスの約束（ハーネス契約）は、evaloom のリポジトリに正本を置き、版を付ける。ハーネスを作るときは、Evaloom の仕様全体ではなく、この契約の決まった版だけを読めば作れるようにする（requirements 原則5）。
- ハーネスが外へ出すときに使う鍵（GitHub など）は Evaloom が保管し、ハーネスの「出す部分」を動かすときだけ渡す（2026-11-10 本人決定）。
