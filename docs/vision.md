# Evaloom とは

この文書は、Evaloom が何をするもので、何をしないものかを決める正本である。requirements.md と docs/specs/ の仕様は、この文書に従う。食い違ったときは、この文書に合わせて requirements と仕様を直す。この文書を変えてよいのは本人だけである。

2026-11-09〜10 の本人との相談をもとに書いた。2026-11-10 の2回目の相談（requirements と仕様の仕分け、`docs/vision-alignment.md`）で、本人の指示により承認の場所、準備の段、Project が持つもの、用語を書き換えた。末尾に本人の言葉を原文のまま残す。

## 1. 一言で

Evaloom は、Linear などから仕事を受け取り、どの Project またはスペシャルハーネスに頼むかを決めて振り分け、結果を返すオーケストラである。仕事そのもの（準備し、作業し、確かめ、出す）はスペシャルハーネスが行う。

開発の仕事だけを扱うものではない。開発、X の運用、調査など、種類の違う仕事を同じ仕組みで扱う。小さなアプリやスペシャルハーネスを重ねていくための土台にする。

## 2. 用語（2026-11-10 本人決定）

仕事を動かす仕組みは3つの層に分かれる。

| 呼び名 | 指すもの | 役目 |
|---|---|---|
| マクロハーネス | Evaloom | 仕事を受け取り、振り分け、順番を待たせ、本人の判断を取り、結果を返す |
| スペシャルハーネス | software-engineer など、仕事の種類ごとのやり方一式 | 指示、スキル、準備・確かめる・出すのプログラムを持ち、仕事の中身をこなす |
| ミクロハーネス | Claude Code、Codex | 指示を受けて、実際に考えて手を動かす AI の道具 |

requirements と仕様では、単に「ハーネス」と書かない。必ず「スペシャルハーネス」か「ミクロハーネス」と書き分ける。Evaloom は仕様の中では「Evaloom」と書き、「マクロハーネス」は層の関係を説明するところで使う。

## 3. Evaloom がやること

1 件の仕事は、次の流れで進む。Evaloom が受け持つのは 1・2・3・7・8 である。

| 段 | 中身 | 担当 |
|---|---|---|
| 1 入る | Linear から仕事を受け取る。手動でも作れる。ほかの入口（定期実行など）は後で足す | Evaloom |
| 2 振り分ける | どの Project またはスペシャルハーネスに頼むかを、Issue のラベルで決める。ラベルが無い、または決まらないときは、AI が Issue を読んで振り分け先を提案し、本人が承認してから実行する | Evaloom |
| 3 順番待ち | 同時に動かす数を制御し、状態を管理する | Evaloom |
| 準備（任意） | 作業に要るものをそろえる（開発ならリポジトリの取得やライブラリの導入）。要らない仕事では使わない | スペシャルハーネス |
| 4 作業する | 仕事の中身をこなす | スペシャルハーネス |
| 5 確かめる | 結果が基準を満たしているかを確かめる | スペシャルハーネス |
| 6 出す | 結果を外に出す（PR、下書き、コメントなど） | スペシャルハーネス |
| 7 承認する | 本人の承認が要る操作を、操作の直前に本人に承認してもらう | Evaloom |
| 8 返す | Linear へのコメントと状態の変更、通知、管理画面、記録 | Evaloom |

加えて、Evaloom は次を受け持つ。

- **スペシャルハーネスの登録と版の固定**: どのスペシャルハーネスのどの版で仕事をしたかを記録する。
- **安全な場所の用意**: 準備・5・6 の中身はスペシャルハーネスが決めるが、作業中の AI が書き換えたり、鍵を使ったりできない場所で動かす。その場所（隔離、鍵の保管、決まった版から読み出すこと）を用意するのは Evaloom である。7 で何を承認の対象にするかはスペシャルハーネスが宣言し、承認の画面と記録は Evaloom が持つ。
- **鍵を持つ段は AI を使わない**（2026-11-10 本人決定）: 鍵や外への接続を受け取る段（準備と出す）は、スペシャルハーネスの決まった版のプログラムだけで動かし、AI（ミクロハーネスやモデル）を呼ばない。文章を考えるなど AI の仕事は、鍵の無い作業の段で済ませておく。作業の段には、モデルへの接続のほかは、鍵も外への接続も渡さない。
- **承認と中身の結び付け**: スペシャルハーネスは、承認を求めるときと出す直前に、中身の識別子を Evaloom に渡す。Evaloom は2つを比べ、承認したときと中身が変わっていたら承認を無効にする。確かめたものと出すものが同じかを見張るのは、スペシャルハーネスである（2026-11-10 本人決定）。
- **記録と受け渡し**: スペシャルハーネスの成果物を記録として持ち、同じスペシャルハーネスの次の仕事に参考として渡す。
- **振り分けの提案**（2026-11-10 本人決定）: 振り分けはラベルで決めるのが基本である。Linear の Team は振り分けに使わない。ラベルで決まらない Issue だけ、AI が中身を読んで「実行場所はこれでよいか」を提案し、本人の承認を待つ。AI は提案するだけで、承認なしに実行を始めない。Issue の本文は外から来た文であり、AI がそれに引きずられて誤った振り分けをしても、本人の承認で止められるようにするためである。
- **本人の判断は管理画面の1か所で受け付ける**（2026-11-10 本人決定）: 振り分けの承認、操作の承認、止まった仕事の続行、作業中の AI からの質問への回答は、すべて管理画面で受け付ける。Linear には「管理画面で判断待ち」と知らせるだけにする。本人が Linear で振り分けのラベルを付けたときは、承認ではなく、普通の振り分けとして扱う。管理画面で判断した結果は、Evaloom が Linear に書き戻す（振り分けのラベルを付ける、状態を変える）。Evaloom が付けてよいラベルは振り分けのラベルだけで、起動の合図のラベル（`ai-ready`）には触らない。

## 4. Evaloom がやらないこと

- 仕事の中身（準備・4・5・6）を決めること。例えば worktree、テスト、PR は開発のスペシャルハーネスのやり方であり、Evaloom の仕組みとしては持たない。
- 特定の種類の仕事を前提にすること。Project（Git リポジトリ）は振り分け先の1つであり、振り分け先そのものではない。リポジトリを持たない仕事は、スペシャルハーネスに直接振り分ける。
- 仕事の種類に固有の情報を持つこと（2026-11-10 本人決定）。例えば開発のテストコマンドや setup は、開発のスペシャルハーネスが持つ。Evaloom は必要なときにスペシャルハーネスを見にいく。Evaloom の Project が持つのは、次の6つだけにする。モデルが起こす失敗への対策も、各スペシャルハーネスの中で完結させる。
  - 名前
  - 振り分けのラベル
  - 頼むスペシャルハーネス
  - そのスペシャルハーネスに渡す値（中身は Evaloom が解釈しない）
  - 承認を省く設定（どの承認を省くか。2026-11-10 本人決定）
  - 動かすマシン（Runner）の指定（2026-11-10 本人決定）
- 本人の代わりに外へ公開すること。公開やマージのような戻せない操作は、本人の承認を通す。

## 5. 迷ったときの基準

- **その処理は、仕事の種類によって中身が変わるか。** 変わるならスペシャルハーネスの管轄、変わらないなら Evaloom の管轄である。
- **作業中の AI が、合否の基準や鍵に触れられるか。** 触れられるなら、置き場所が間違っている（requirements 原則13・14・15）。
- **本人が「思っていたのと違う」と言える形で見せたか。** 仕様を確定する前に、仕事が入ってから返るまでの流れ図を本人に見せる。

## 6. スペシャルハーネスとの約束と鍵

- Evaloom とスペシャルハーネスの約束（ハーネス契約）は、evaloom のリポジトリに正本を置き、版を付ける。スペシャルハーネスを作るときは、Evaloom の仕様全体ではなく、この契約の決まった版だけを読めば作れるようにする（requirements 原則5）。
- スペシャルハーネスが外とやり取りするときに使う鍵（GitHub など）は Evaloom が保管し、スペシャルハーネスの「準備」と「出す部分」を動かすときだけ渡す（2026-11-10 本人決定）。準備の段に渡すのは読み取り用の鍵だけにする。
