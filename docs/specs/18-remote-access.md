# 18. 別端末からのアクセスと本人のログイン 仕様

**親**: [`00-overview.md`](./00-overview.md) ｜ **担当**: Backend（ログイン画面は Frontend） ｜ **範囲**: requirements 15.5 の「別の端末からのアクセスは、認証・認可と通信経路の保護を実装した後に対応する。将来は Tailscale などを使った安全なリモートアクセスを想定する」

この文書は下書きである。本人が決めた値は「決定」と書き、決まっていない点は「案」として 00-overview.md の要確認リスト（Q88〜Q95）に載せている。

## 1. 目的

- MacBook Air やスマートフォンなど、Mac mini 以外の本人の端末から管理画面を使えるようにする（requirements 15.5）。
- 公開するのは Tailscale のネットワーク（tailnet）の中だけにする。インターネットには公開しない。Mac mini のポートも開けない（requirements 2.2、15.2）。
- 起動のたびに一回限りのログイン URL を取りに行く手間をなくす。本人は ID とパスワードでログインし、一度ログインした端末は有効期限まで、Control Plane を再起動してもログインしたままにする。
- 同じマシンの不正なプログラムと、ブラウザ経由の CSRF・DNS リバインディングへの対策（[`01-architecture.md`](./01-architecture.md) 3.4）は弱めない。

## 2. 入出力

| 区分 | 内容 |
|---|---|
| 入力 | 本人の ID とパスワード（ログイン画面）、セッション Cookie、`X-CSRF-Token`、要求の Host / Origin |
| 出力 | owner_credentials、owner_sessions（本書 3.8）、セッション Cookie、audit_logs（ログインの成功・失敗、パスワードの設定） |

テーブルの定義は本書 3.8 に書き、[`02-data-model.md`](./02-data-model.md) から参照する。

## 3. 処理詳細

### 3.1 公開の経路（決定: Tailscale のネットワーク内だけ）

- `evaloomd` は今までどおり `127.0.0.1:<port>` だけで待ち受ける。待ち受けのホストを変えるフラグは作らない（[`01-architecture.md`](./01-architecture.md) 3.2）。
- 別端末からは `tailscale serve` を使い、tailnet の中の HTTPS（`https://orionmac-mini.tailb76d84.ts.net`）から `http://127.0.0.1:<port>` へ中継する。TLS は Tailscale が終端する。
- Tailscale Funnel（インターネットへの公開）は使わない（決定）。
- `tailscale serve` の設定は本人が1回だけ行う（9章の人間タスク）。Evaloom は Tailscale の設定を書き換えない。
- tailnet の中で管理画面に届く端末を本人の端末に絞るため、Tailscale のアクセス制御（ACL）を設定する案（Q95）。設定するかどうかと内容は本人が決める。

### 3.2 許可する Host と Origin

01 の 3.4 は Host / Origin が `127.0.0.1:<port>` 以外の要求を拒否している。これに、Tailscale の名前を1つ足す。

| 経路 | Host | Origin |
|---|---|---|
| Mac mini から直接 | `127.0.0.1:<port>` | `http://127.0.0.1:<port>` |
| tailnet から（`tailscale serve` の中継） | `orionmac-mini.tailb76d84.ts.net`（決定） | `https://orionmac-mini.tailb76d84.ts.net` |

- 許可する Tailscale の名前は、起動時の設定で1つだけ指定する（案: `evaloomd -remote-host <名前>`、Q88）。指定が無ければ今までどおり `127.0.0.1:<port>` だけを許可する。
- 値は完全一致で照合する。ワイルドカードや接頭辞での一致は使わない。
- `tailscale serve` が中継するときの Host と送信元アドレスの実際の値は、実装時に実測して確かめる。中継された要求は `127.0.0.1` から届くため、送信元アドレスでは区別しない。
- Vite の開発サーバの例外（01 の 3.4）は変えない。

### 3.3 本人の資格情報

- 利用者は本人1人のまま（requirements 15.5）。ID とパスワードの組は1つだけ持つ。
- ID とパスワードは、Mac mini のターミナルから CLI で設定する。案: `evaloomd -db <DB> owner set-password -id <ID>`。パスワードは画面に表示せずに標準入力から2回読み、一致したときだけ保存する（Q89）。
- パスワードを忘れたときも、同じコマンドで設定し直す。設定し直すと、それまでのセッションはすべて無効にする（案、Q89）。
- 管理画面からはパスワードを設定も変更もできない（案、Q89）。初回の設定を画面で受け付けると、同じマシンの不正なプログラムに先に設定されるおそれがあるため。
- パスワードはハッシュだけを保存する。方式は argon2id にする案（Q90）。最小の長さも Q90 で決める。
- 設定と再設定は audit_logs に残す。ハッシュとパスワードの値は記録しない。

### 3.4 ログイン

- 管理画面は、セッションが無いときにログイン画面を出す。ID とパスワードを入れて送る。
- `POST /auth/login`（本文は `{ "id", "password" }`）で照合する。成功したらセッションを作り（3.5）、Cookie を返す。
- 失敗したら 401 を返す。ID が違うのかパスワードが違うのかは区別して返さない。
- ログインの成功・失敗は audit_logs に残す。経路（直接か tailnet か）と時刻を記録し、パスワードの値は記録しない。
- 続けて失敗したときの抑止は案とする。5回続けて失敗したら60秒間ログインを受け付けない（Q91）。
- パスワードが未設定のときは、ログイン画面に「Mac mini で `evaloomd owner set-password` を実行してパスワードを設定する」ことを出す。ログインは受け付けない。

### 3.5 セッション

- ログインに成功するたびに、その端末用のセッションを1つ作る。端末ごとに別のセッションになる。
- セッションの値は 32 バイトの暗号学的乱数にする。DB にはハッシュ（SHA-256）だけを保存し、値そのものは保存しない。
- 有効期限は、ログインした時刻から3日（決定）。使っている間に延ばすかどうかは案とし、延ばさない（3日たったらログインし直す）案とする（Q92）。
- セッションは DB に保存するので、Control Plane を再起動しても有効期限までは使える。
- Cookie は `HttpOnly; SameSite=Strict; Path=/` に加え、`Max-Age` を有効期限までの秒数にする。tailnet からの HTTPS では `Secure` を付ける。Mac mini からの `http://127.0.0.1` では付けない（案、Q93）。
- CSRF トークンはセッションごとに作り、`GET /api/session` で返す（今の形を保つ）。状態を変える要求の `X-CSRF-Token` は、そのセッションのトークンと照合する。
- 期限が切れたセッションは使えない。期限切れの行を消す時期は実装時に確定する（起動時と1日1回などの案）。
- 自分の端末からのログアウトは案とする（`POST /auth/logout` でそのセッションを消す、Q94）。
- ほかの端末のセッションを切る操作は作らない（決定）。必要になったら、3.3 のパスワードの再設定ですべてのセッションを無効にできる。

### 3.6 一回限りのログイン URL の廃止

- 起動時に一回限りのログイン URL を作らない。標準出力・標準エラー・ログにも出さない（01 の 3.4 の Q2 の案を置き換える）。
- `/auth/login?token=...` の GET は受け付けない（404）。
- テスト・`make demo`・E2E は、起動の前に CLI でテスト用のパスワードを設定し、`POST /auth/login` でログインする形に変える。`make demo` は、表示していたログイン URL の代わりに、管理画面の URL とテスト用の ID・パスワードを表示する（案、Q89）。

### 3.7 重要な操作でのパスワードの入れ直し

- 承認・却下・承認ポリシーの変更などの操作でも、パスワードを入れ直させない（決定）。ログイン中のセッションと CSRF トークンだけで行える。

### 3.8 データモデル

**owner_credentials**（本人の資格情報。行は0件か1件）

| 列 | 型 | 説明 |
|---|---|---|
| id | TEXT PK | 本人のログイン ID |
| password_hash | TEXT | パスワードのハッシュ（3.3 の方式の形式で保存） |
| created_at | TEXT | 最初に設定した時刻 |
| updated_at | TEXT | 最後に設定した時刻 |

**owner_sessions**（端末ごとのセッション）

| 列 | 型 | 説明 |
|---|---|---|
| id | TEXT PK | ULID |
| token_hash | TEXT UNIQUE | セッションの値の SHA-256 |
| csrf_token_hash | TEXT | CSRF トークンの SHA-256 |
| created_at | TEXT | ログインした時刻 |
| expires_at | TEXT | 有効期限（created_at + 3日） |
| via | TEXT | ログインした経路。`loopback` / `tailnet` |

- パスワードを設定し直したら、owner_sessions の行をすべて消す（3.3）。
- 列の追加・変更はマイグレーションで行う（[`02-data-model.md`](./02-data-model.md) 3.1）。

## 5. インターフェース

| メソッド | パス | 用途 | 認証 |
|---|---|---|---|
| POST | `/auth/login` | ID とパスワードでログインし、セッション Cookie を受け取る | なし（Host / Origin の照合はする） |
| POST | `/auth/logout` | 自分のセッションを消す（案、Q94） | 本人のセッション + CSRF |
| GET | `/api/session` | ログイン中かどうかと CSRF トークンを返す（今の API） | 本人のセッション |

CLI: `evaloomd -db <DB> owner set-password -id <ID>`（案、Q89）。

API の共通規約（エラーの形、401 / 403 の使い分け）は [`01-architecture.md`](./01-architecture.md) 5.3 に従う。

## 6. エラー処理

| 事象 | 扱い |
|---|---|
| ID かパスワードが違う | 401。どちらが違うかは返さない。audit_logs に失敗を残す |
| 続けて失敗した | 3.4 の抑止の間は 429 を返し、照合しない（案、Q91） |
| パスワードが未設定 | ログインを受け付けない。ログイン画面に設定の手順を出す |
| セッションの期限切れ・不明な値 | 401。管理画面はログイン画面へ移る |
| Host / Origin が許可の値以外 | 403。audit_logs に残す（01 の 6章） |
| CSRF トークンが無い・違う | 403。audit_logs に残す |
| DB への書き込みに失敗 | ログイン・ログアウトを失敗させる（Fail Closed、01 の 3.5） |

14 の権限境界テストに足す項目:

- 許可していない Host（例: `evil.example`）と、許可した名前に似た Host（例: `orionmac-mini.tailb76d84.ts.net.evil.example`）の要求が 403 になる。
- 期限切れのセッションの Cookie で本人用 API を呼ぶと 401 になる。
- Control Plane を再起動しても、期限内のセッションで本人用 API を呼べる。
- パスワードの再設定の後、前のセッションで本人用 API を呼ぶと 401 になる。
- 一回限りのログイン URL（`/auth/login?token=...`）が使えない。
- Runner のトークンで `POST /auth/login` 以外の本人用 API を呼ぶと、今までどおり拒否される。

## 7. スコープ外

- インターネットへの公開（Tailscale Funnel、公開 HTTPS エンドポイント、トンネル）
- 複数の利用者、利用者の管理、権限の種類の追加（requirements 15.5）
- ほかの端末のセッションを切る操作（決定）
- 重要な操作でのパスワードの入れ直し（決定）
- 二要素認証、パスキー
- Tailscale の ACL の設定そのもの（本人が Tailscale の管理画面で行う）
- 管理画面からのパスワードの設定・変更（案、Q89）
